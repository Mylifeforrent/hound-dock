## Findings and resolution

- **P1 — Dialog focus trap does not trap focus (open).** `focusables()` in `docs/03_design/prototype/app.js:587–590` selects `[href]`, which includes every `<use href="#i-…">` inside the inline SVG icons. The `offsetParent !== null` filter does not remove SVG `<use>` elements because `offsetParent` is `undefined` (and `undefined !== null`), so the Manage drawer exposes 23 items and the last is a `<use tabindex="-1">`. With keyboard navigation, Tab from the last real control (Settings) lands on `BODY` outside the drawer before returning to the close button. The same helper is used by `#modal`, so skill/MCP/task/chat dialogs have the same leak. This contradicts CHG-005 verification row 20 and `design_system.md:307`. Suggested fix (not applied): restrict the selector to native tabbable elements and filter `element.tabIndex >= 0` / exclude SVG namespace nodes. **File:line:** `app.js:587–590`, `app.js:2169–2193`.
- **P2 — Audit date select has no visible focus state.** `styles.css:1673–1676` sets `border:0; outline:0` on `.select-box select`, and there is no `.select-box:focus-within` rule. At runtime, focusing `#audit-period` yields `outline-style:none`, `outline-width:0px`, parent border `rgb(142,134,116)` and no box-shadow. Keyboard users can reach the control but cannot see where focus is. This fails acceptance criterion 4 and `design_system.md:306`. **File:line:** `styles.css:1673–1676`.
- **P2 — Design-system typography/card tokens do not match the CSS.** `design_system.md:110` assigns `--text-xl` (18px) to “Card title”, but `design_system.md:217` says card titles are 20px and `.card-title` in `styles.css:2900` is a raw 20px. `--card-pad` is documented as 16px (`design_system.md:149`), but registry cards use raw `15px 15px 13px 18px` (`styles.css:2829`). The doc’s type/token tables and component prose disagree. **File:line:** as cited.
- **P2 — Theme/token-discipline claims exceed the implementation.** `design_system.md:48` says “Dark mode overrides semantic roles only; components do not branch on the theme”, but `styles.css:1169–1174` and `:2488` contain `[data-theme="dark"]` component rules. `design_system.md:30` and `:46–47` say raw values live only in the primitive layer, but 18 raw `rgba()` colors remain in component rules (e.g. `styles.css:595, 597, 695, 706–707, 765, 912, 974, 4413`). These are documentation/implementation drift, not visual regressions.
- **P2 — Control-border contrast range is understated for dark canvas.** `design_system.md:301` states 3.20–3.55:1 across canvas, surface and raised. Recomputed: light canvas 3.20, light surface 3.43, light raised 3.55; dark canvas 3.73, dark surface 3.55, dark raised 3.31. All pairs pass 3:1, but the stated upper bound is wrong. **File:line:** `design_system.md:301`.
- **P2 — Review index not updated.** `docs/13_changes/CHG-005-prototype-visual-system.md:19` lists `docs/12_reviews/README.md` as an affected path, but `docs/12_reviews/README.md:7–10` still ends at CHG-004 and does not list CHG-005. Out of Verifier write scope; Tech Lead action.
